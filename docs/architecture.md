# 설계

[← README](../README.md)

## 폴더 구성

```
lib/
  engine/     홀덤 규칙. Flutter도 Firebase도 모르는 순수 Dart.
  net/        방을 잇는 통신 계층. Firestore와 로컬 두 가지 구현.
  game/       Flame으로 테이블을 그리는 쪽.
  ui/         화면, 오버레이, 테마.
  data/       기기에 남기는 설정(닉네임).
```

## 진행을 누가 맡는가

방장 기기가 규칙 판정을 전담한다.

```
참가자                     Firestore                    방장
  │  commands/{id} 생성  →     │
  │                            │  → 스냅샷 →              │  HoldemEngine.apply()
  │                            │                          │  규칙 검사 후 반영
  │  ← rooms/{code} 스냅샷 ←   │  ← 한 번에 batch 쓰기 ←   │
  │  ← private/{내 uid} ←      │
```

참가자는 테이블 문서를 직접 고칠 수 없다. 요청만 남기고, 반영 여부는 방장의
엔진이 정한다. 문서를 직접 건드리거나 화면이 한발 늦은 상태에서 버튼을 눌러도
판이 어그러지지 않는다.

- 명령에는 보낼 때 보던 `handNumber`와 `actionCounter`가 함께 실린다. 둘이
  어긋나면 방장이 버린다. 연타하거나 통신이 늦어도 액션은 한 번만 반영된다.
- 남은 덱과 모두의 홀 카드는 방장만 읽는 `secret/host` 문서에 남는다. 방장
  기기가 잠깐 끊겼다 돌아와도 돌리던 판을 그대로 이어 간다.
- 제한 시간을 넘기거나 접속이 끊긴 사람은 방장이 대신 체크 또는 폴드한다.

이 구조의 대가는 분명하다. 방장이 나가면 판이 멈추고, 서버 권위 모델이 아니므로
방장이 마음먹으면 자기 기기의 앱을 고칠 수 있다. 돈이 오가지 않는 친구끼리의
판을 전제로 한 선택이고, 그 대신 Cloud Functions 없이 무료 요금제 안에서 돈다.
모르는 사람과 붙이려면 엔진을 Cloud Functions이나 별도 Dart 서버로 옮기면 된다.
엔진이 순수 Dart인 것은 그 때문이다.

## 홀 카드를 지키는 방법

문서를 네 갈래로 나눈다.

| 경로 | 내용 | 누가 읽나 |
|---|---|---|
| `rooms/{code}` | 공개 테이블 상태 | 로그인한 누구나 |
| `rooms/{code}/private/{uid}` | 그 사람의 홀 카드 | 본인만 |
| `rooms/{code}/secret/host` | 남은 덱과 전원의 홀 카드 | 방장만 |
| `rooms/{code}/commands/{id}` | 참가자 요청 | 방장만 (쓰기는 본인 것만) |

공개 문서에는 남의 홀 카드가 애초에 실리지 않는다. 쇼다운에서 공개된 자리만
예외다. 이 경계는 `firestore.rules`가 강제하므로 앱을 고쳐도 뚫리지 않는다.

규칙을 고쳤다면 배포한 뒤 [실제로 막히는지 확인](deployment.md#보안-규칙-배포와-검증)한다.

## 규칙 엔진

`lib/engine/`은 화면도 네트워크도 모른다. `TableState` 하나를 받아 고쳐 나갈
뿐이라, 나중에 진행을 서버로 옮기고 싶으면 그대로 떼어 쓸 수 있다.

구현한 것:

- 2~9인 노 리밋 홀덤, 버튼 · 블라인드 이동 (2인 헤즈업 순서 포함)
- 프리플랍 빅 블라인드 옵션
- 최소 레이즈 폭, **부족한 올인은 베팅을 다시 열지 않는다**
- 아무도 받아 주지 않은 베팅 반환
- 메인 팟과 사이드 팟, 자격이 같은 층은 하나로 합침
- 무승부 분배, 나누어떨어지지 않는 칩은 버튼 왼쪽부터
- 7장 중 최고 5장 족보 판정 (A-2-3-4-5 포함)

테스트가 이 항목들을 하나씩 짚는다.

```sh
fvm flutter test
```

### 베팅이 다시 열렸는가

칩이 모자라 최소 폭에 못 미치게 올린 올인은 앞사람의 레이즈 권한을 되살리지
않는다. 차액을 맞출 수는 있어도 다시 올릴 수는 없다.

이걸 위해 상태를 따로 두지 않았다. 제대로 된 레이즈가 나왔을 때만 다른 사람의
`hasActed`가 풀리므로, 이 플래그 하나가 «베팅이 다시 열렸는가»를 그대로
나타낸다. 레이즈 가능 여부는 `!seat.hasActed`로 읽으면 된다.

## 화면

테이블은 Flame이 그리고 버튼과 안내는 Flutter 위젯이 맡는다. 위아래 띠가 차지할
높이를 미리 비워 두기 때문에, 내 차례가 오고 갈 때 테이블이 커졌다 작아졌다
하지 않는다.

좌석 타원은 고정 해상도 대신 매번 화면 비율을 보고 계산한다. 위아래 여백을 다르게
잡는 것이 핵심이다 — 위쪽 자리는 이름표 위로 카드가 고개를 내밀고, 아래쪽 내
자리는 카드가 테이블 안쪽으로 뻗는다. 같은 값을 쓰면 세로 화면에서 위쪽 자리
카드가 화면 밖으로 잘린다.

### Flame을 쓸 때 걸렸던 것

`onLoad` 안에서 `add`를 기다리면 안 된다. 컴포넌트가 실제로 붙는 것은 `onLoad`가
끝난 뒤라, 기다리는 순간 서로를 기다리며 영원히 로딩 화면에 머문다. 예외가 나지
않아 원인이 보이지 않는다. 로딩 전에 들어온 상태는 `onMount`에서 다시 얹는다.
